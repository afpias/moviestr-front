# Инженерный стандарт: UI и доступность

Конкретная композиция игровой доски и её наблюдаемое поведение заданы в
[SPEC-004](./specs/SPEC-004-game-interface.md). Этот стандарт определяет общие правила реализации интерфейса.

## UI-kit

Базовые controls добавляются из официального реестра shadcn-vue и хранятся локально в `shared/ui`. Они используют
штатные примитивы Reka UI. Если нужный компонент существует в shadcn-vue, параллельный самописный аналог не создаётся.

- Компоненты импортируются через публичный API `@shared/ui`.
- Глобальная регистрация UI-компонентов не применяется.
- Tailwind utility-классы разрешены только внутри `shared/ui`.
- Pages, widgets, features и entities используют соседние scoped CSS-файлы.
- Иконки берутся из `@lucide/vue`; иконка без видимого текста получает доступное имя.
- Сгенерированный код shadcn-vue можно адаптировать и считать кодом проекта.

## Design tokens

Повторяемые цвета, интервалы, радиусы и тени задаются CSS custom properties в `shared/assets`:

```css
:root {
	--app-color-background: ...;
	--app-color-surface: ...;
	--app-color-text: ...;
	--app-color-accent: ...;
	--app-radius-medium: ...;
	--app-space-medium: ...;
}
```

Название token описывает роль, а не конкретный цвет. Компонент не добавляет случайное hex-значение, если подходящий
token уже существует.

## Темы

- Поддерживаются `dark` и `light` по [SPEC-005](./specs/SPEC-005-persistence-theme.md).
- Тёмная тема остаётся основной кинематографичной темой.
- Контраст текста и интерактивных состояний проверяется в обеих темах.
- Переключение темы не перезагружает страницу и не сбрасывает focus.

## Адаптивность

Используется mobile-first подход. Минимальная поддерживаемая ширина — 360 px.

- 360–599 px — компактный мобильный интерфейс;
- 600–1023 px — широкий мобильный или планшетный;
- 1024 px и больше — desktop.

Основные действия доступны без горизонтального скролла. Изображения сохраняют пропорции. Интерактивная цель имеет
достаточный размер для сенсорного ввода, а текст не обрезается при увеличении масштаба браузера.

Поддерживаются актуальные версии Chrome, Firefox, Safari и Edge. Legacy-браузеры не входят в требования.

## Доступность

Цель — практическая доступность основного сценария без заявления о формальной WCAG-сертификации.

Обязательно:

- полный основной сценарий с клавиатуры;
- видимый `focus-visible`;
- связанный label или доступное имя поля;
- текстовое обозначение ошибки и значимого состояния, а не только цвет;
- предсказуемый focus после отправки ответа и появления результата;
- осмысленный `alt`, не раскрывающий фильм;
- достаточный контраст основного текста и controls;
- поддержка `prefers-reduced-motion` для существенных анимаций.

Ручной screen reader аудит и формальный WCAG-отчёт остаются известным ограничением.

## Состояния компонента

Интерактивный компонент проектируется для `default`, `hover`, `focus-visible`, `active`, `disabled`, `loading` и `error`,
если состояние применимо. Skeleton показывает ожидаемую структуру. Spinner используется только для локального действия
неизвестной длительности и не заменяет всю страницу.

## Проверка

- Component tests проверяют доступные имена, disabled/loading и клавиатурное поведение.
- Адаптивность и focus order дополнительно проверяются вручную на контрольных диапазонах.
- Значимое визуальное требование должно иметь ID из `SPEC-004` и запись в её таблице трассировки.

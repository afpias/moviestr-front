# UI, темы и доступность

## shadcn-vue

Базовые controls добавляются официальным CLI shadcn-vue и хранятся локально в `shared/ui`. Компоненты shadcn-vue
используют штатные примитивы Reka UI; прямые самописные аналоги существующих компонентов shadcn-vue не создаются.

Правила:

- Компоненты импортируются локально через публичный API `shared/ui`.
- Глобальная регистрация UI-компонентов не применяется.
- Tailwind CSS применяется только внутри `shared/ui`; страницы продолжают использовать внешние scoped CSS-файлы.
- Визуальные значения связываются с design tokens проекта через CSS variables.
- Иконки берутся из `@lucide/vue` и получают доступное имя, когда не сопровождаются текстом.
- Интерактивные controls используют доступность и focus management, предоставленные компонентами shadcn-vue и Reka UI.

Сгенерированный код можно адаптировать под интерфейс Moviestr, не заменяя его параллельной самописной реализацией.

## Темы

Поддерживаются светлая и тёмная темы.

- Начальное значение берётся из `moviestr:theme:v1`.
- Если сохранённого выбора нет, используется тёмная тема как основная для кинематографичного интерфейса.
- Пользовательский выбор имеет приоритет над системным.
- Тёмная тема активируется классом `.app-dark` на корневом элементе.
- Переключение темы не должно перезагружать страницу.

## Визуальное направление игры

Игровой экран использует тёмную кинематографичную композицию по референсу Allspot:

- почти чёрный фон, глубокие зелёные поверхности и яркий зелёный accent;
- общий игровой контейнер не получает внешнюю рамку;
- кадр фильма является главным визуальным объектом и занимает центральную колонку;
- над кадром нет отдельного заголовка режима или призыва «Назови этот фильм»;
- выбор сложности отображается компактными цветными pills по центру над кадром и небольшими кнопками без описаний в левой панели;
- над сложностью расположен раскрывающийся выбор из восьми жанров с отдельной иконкой для каждого варианта, под ней — действие «Перезапустить раунд»;
- второстепенная информация визуально приглушена, границы тонкие, поверхности без тяжёлых теней;
- раскрытое меню жанров имеет непрозрачный фон, совпадает по ширине с trigger и использует симметричную сетку пунктов;
- на мобильном экране боковая панель превращается в горизонтальный список режимов;
- элементы управления видео, звуком и размером экрана не добавляются: в MVP используются только статические изображения;
- основная кнопка показывает «Пропустить», пока фильм не выбран из автодополнения, и «Угадать» после выбора;
- на последнем кадре действие «Пропустить» меняется на «Сдаться»;
- варианты автодополнения раскрываются над полем и перекрывают кадр, не сдвигая layout;
- служебные уведомления об открытии следующего кадра и перезапуске раунда не отображаются;
- номер кадра не дублируется поверх изображения;
- правая колонка показывает только номер кадра и формат, без повторения активного режима;
- режимы сложности интерактивны прямо на игровом экране и не требуют отдельного старта;
- очки в одиночном режиме не отображаются.
- после ответа центральная игровая область показывает постер, правильное локализованное и оригинальное название и результат раунда без модального окна и вводного текста;
- результат победы содержит кнопку «Далее», результат поражения — кнопку «Повторить»;
- основной accent всего приложения соответствует сложности: зелёный, жёлтый, оранжевый, красный или фиолетовый;
- на desktop игровой экран помещается в viewport без вертикального скролла страницы.

Собственные tokens группируются по назначению:

```css
:root {
	--app-color-background: ...;
	--app-color-surface: ...;
	--app-color-text: ...;
	--app-color-accent: ...;
	--app-radius-medium: ...;
	--app-space-medium: ...;
}
```

Название token описывает роль, а не конкретный цвет.

## Адаптивность

Минимальная поддерживаемая ширина viewport — 360 px. Используется mobile-first подход.

Контрольные диапазоны, а не жёсткие устройства:

- 360–599 px — компактный мобильный интерфейс;
- 600–1023 px — широкий мобильный или планшетный;
- 1024 px и больше — desktop.

Критерии:

- кадр фильма сохраняет ожидаемое соотношение сторон и не растягивается;
- основные действия доступны без горизонтального скролла;
- интерактивная цель имеет достаточный размер для сенсорного управления;
- встроенный результат помещается по высоте игровой области;
- текст не обрезается при увеличении масштаба браузера.

Поддерживаются актуальные версии Chrome, Firefox, Safari и Edge. Дополнительные legacy-браузеры не входят в требования.

## Уровень доступности

Цель MVP — практическая доступность основного сценария без заявления о формальной сертификации WCAG.

Обязательно:

- игра полностью управляется клавиатурой;
- видимый focus не удаляется;
- поля имеют связанный label или доступное имя;
- иконка без текста имеет `aria-label`;
- состояние ошибки сообщается текстом, не только цветом;
- после отправки ответа фокус остаётся предсказуемым;
- после появления результата фокус можно последовательно перевести на основное действие;
- изображения имеют осмысленный `alt`, не раскрывающий ответ;
- основной текст и интерактивные состояния имеют достаточный контраст;
- обязательная анимация не используется; существенная анимация учитывает `prefers-reduced-motion`.

Желательно, но не блокирует MVP:

- полная ручная проверка screen reader;
- формальный отчёт WCAG;
- расширенные live-region объявления для каждого визуального изменения.

## Состояния компонентов

Интерактивный компонент проектируется минимум для состояний:

- default;
- hover, если доступна мышь;
- focus-visible;
- active;
- disabled;
- loading;
- error, если компонент работает с вводом или данными.

Skeleton используется для ожидаемой структуры, вращающийся индикатор — для локального действия неизвестной длительности.
Индикатор загрузки не должен заменять всю страницу при отправке ответа.
При смене сложности или жанра сохраняется каркас страницы: обновляется только центральная область кадра.

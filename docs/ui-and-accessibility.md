# UI, темы и доступность

## PrimeVue

Используется PrimeVue 5 в styled mode с темой Aura и PrimeIcons.

Правила:

- PrimeVue подключается один раз в app provider.
- Компоненты импортируются локально для tree-shaking.
- Глобальная регистрация отдельных UI-компонентов не применяется.
- Повторяющаяся конфигурация оборачивается в компонент `shared/ui` только после второго реального использования.
- Визуальные изменения выполняются через design tokens, CSS variables и Pass Through API.
- Копирование внутренней DOM-структуры PrimeVue в собственные компоненты запрещено.

Официальная схема установки описана в [PrimeVue Installation](https://primevue.dev/installation), а Aura и dark mode — в
[Styled Mode](https://primevue.dev/theming/styled).

## Темы

Поддерживаются светлая и тёмная темы.

- Начальное значение берётся из `moviestr:theme:v1`.
- Если сохранённого выбора нет, учитывается `prefers-color-scheme`.
- Пользовательский выбор имеет приоритет над системным.
- Тёмная тема активируется классом `.app-dark` на корневом элементе.
- Переключение темы не должно перезагружать страницу.

Собственные tokens группируются по назначению:

```css
:root {
	--app-color-background: ...;
	--app-color-surface: ...;
	--app-color-text: ...;
	--app-color-accent: ...;
	--app-radius-medium: ...;
	--app-space-medium: ...;
}
```

Название token описывает роль, а не конкретный цвет.

## Адаптивность

Минимальная поддерживаемая ширина viewport — 360 px. Используется mobile-first подход.

Контрольные диапазоны, а не жёсткие устройства:

- 360–599 px — компактный мобильный интерфейс;
- 600–1023 px — широкий мобильный или планшетный;
- 1024 px и больше — desktop.

Критерии:

- кадр фильма сохраняет ожидаемое соотношение сторон и не растягивается;
- основные действия доступны без горизонтального скролла;
- интерактивная цель имеет достаточный размер для сенсорного управления;
- диалог результата помещается по высоте или получает внутренний скролл;
- текст не обрезается при увеличении масштаба браузера.

Поддерживаются актуальные версии Chrome, Firefox, Safari и Edge. Дополнительные legacy-браузеры не входят в требования.

## Уровень доступности

Цель MVP — практическая доступность основного сценария без заявления о формальной сертификации WCAG.

Обязательно:

- игра полностью управляется клавиатурой;
- видимый focus не удаляется;
- поля имеют связанный label или доступное имя;
- иконка без текста имеет `aria-label`;
- состояние ошибки сообщается текстом, не только цветом;
- после отправки ответа фокус остаётся предсказуемым;
- диалог удерживает фокус и возвращает его инициатору;
- изображения имеют осмысленный `alt`, не раскрывающий ответ;
- основной текст и интерактивные состояния имеют достаточный контраст;
- обязательная анимация не используется; существенная анимация учитывает `prefers-reduced-motion`.

Желательно, но не блокирует MVP:

- полная ручная проверка screen reader;
- формальный отчёт WCAG;
- расширенные live-region объявления для каждого визуального изменения.

## Состояния компонентов

Интерактивный компонент проектируется минимум для состояний:

- default;
- hover, если доступна мышь;
- focus-visible;
- active;
- disabled;
- loading;
- error, если компонент работает с вводом или данными.

Skeleton используется для ожидаемой структуры, ProgressSpinner — для локального действия неизвестной длительности. Индикатор загрузки не должен заменять всю страницу при отправке ответа.

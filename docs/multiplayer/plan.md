# План реализации SPEC-006

Статус: утверждено для локального демо. Спецификация: [`spec.md`](./spec.md).

## Подход

Frontend-only заглушка с общим локальным состоянием комнаты и типизированным интерфейсом API. Записи в localStorage
выполняются под Web Lock; storage events уведомляют другие вкладки, локальная подписка — текущую. Heartbeat и общий
deadline обеспечивают восстановление и передачу хоста. Ответ, очки и переход применяются одной атомарной операцией.

Настоящий backend впоследствии реализует тот же контракт с серверной проверкой ответа и доставкой snapshots/events.
Production backend сейчас не добавляется.

## Архитектура

- `app/router.ts` — `/lobby` и `/lobby/:roomId`.
- `pages/lobby` — композиция списка, создания и входа; координация в `model`.
- `pages/room` — композиция участников и игровой сцены; координация в `model`.
- `widgets/lobby-browser`, `room-console` — самостоятельные области страниц.
- `features/create-lobby`, `join-lobby`, `play-multiplayer` — формы и действия; API-вызовы в сегментах `api`.
- `entities/lobby`, `room-player` — отображение настроек комнаты, участников и рейтинга.
- `shared/stores/multiplayer.store.ts` — Setup Store общего состояния и жизненного цикла подписки.
- `shared/api/multiplayer` — контракт адаптера, заглушка, storage-валидация и чистые игровые правила.
- `shared/types/multiplayer.ts` — DTO настроек, комнаты, игрока и команд.
- `shared/ui/input` — штатный Input shadcn-vue; остальные controls использовать из существующего реестра.

## Контракт адаптера

- `listRooms()` — только публичные ожидающие комнаты без секретов.
- `getRoom(roomId, participantId)` — публичное состояние и личный кадр/попытки вошедшего игрока.
- `createRoom(settings, nickname, password)` — создание и гостевой вход хоста.
- `joinRoom(roomId, nickname, password)` — гостевой вход с проверкой мест и пароля.
- `startRoom(roomId)` — старт от двух игроков, только хостом.
- `submitGuess(roomId, roundId, movieId)` и `skipFrame(roomId, roundId)` — изменение личного состояния.
- `leaveRoom(roomId)`, `heartbeat(roomId)`, `retryPreparation(roomId)` — управление соединением и восстановлением.
- `subscribe(callback)` — доставка актуальных snapshots вместо прямого обращения UI к storage.

Команды содержат идентификатор раунда, чтобы ответ на старый фильм не изменил новый. Терминальные ответы и повторно
выбранные ID не начисляют очки повторно. Доступ к хостовым действиям проверяется адаптером.

## Данные

Room хранит настройки, участников, статус, revision, номер фильма, round ID, deadline и использованные TMDB ID.
Данные фильма и пароль доступны только внутренней модели заглушки. Публичное представление содержит очки, результат
последней попытки и личный кадр; правильный ответ появляется только после завершения фильма всеми.

Подготовка фильма происходит вне блокировки записи: короткая атомарная операция резервирует загрузку, затем один
загрузчик получает фильм из TMDB и публикует его при совпадении round ID. Ошибка сохраняется в комнате. Повторный
кандидат отклоняется; перебор ограничен бюджетом. Предзагрузка работает только для разрешённых игроку кадров.

## Этапы

1. Зафиксировать SDD-пакет и контракт заглушки.
2. Реализовать модель комнаты, счёт, timer, reconnect и атомарный storage-адаптер с тестами.
3. Добавить страницы списка и комнаты, формы и игровой widget.
4. Проверить два участника в разных вкладках, гонки, пять кадров, финальный рейтинг и регрессию одиночного режима.

## Риски

- Гонки команд: Web Locks и round ID. Долгие TMDB-запросы не блокируют вход и heartbeat.
- Закрытый загрузчик: lease подготовки истекает, другая вкладка повторяет загрузку.
- Замедление фоновых вкладок: состояние и таймер вычисляются по timestamps, а не числу interval ticks.
- Недоступный localStorage или Web Locks: безопасная ошибка вместо несогласованной имитации.
- Ограничения локальной заглушки обозначены пользователю; перед заменой backend нужны серверная гостевая сессия,
  валидация команд, rate limiting и проверка очков.

## Проверка

- Unit: настройки, права хоста, лимит мест, очки, duplicate/stale commands, timeout, reconnect и ничья.
- Component: создание, пароль и вход, старт, ожидание остальных, состояния игроков и итог.
- Интеграционно: два адаптера с общим storage и последовательной блокировкой выполняют один матч.
- Ручная проверка: несколько вкладок, desktop/360 px, предзагрузка, переходы и доступность.
- Обязательные команды: `yarn validate`, `yarn build`.

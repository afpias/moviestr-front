# Стратегия тестирования

## Инструменты

- Vitest — unit и integration tests.
- Vue Test Utils — поведение Vue-компонентов.
- jsdom — DOM-окружение.
- Vitest mocks — изоляция прямого TMDB-адаптера в тестах stores и компонентов.

Формальный процент покрытия не устанавливается. Отсутствие порога не означает отсутствие тестов: критическая бизнес-логика и пользовательские переходы должны быть проверены.

## Размещение и имена

Тест располагается рядом с тестируемым модулем:

```text
shared/stores/
├── game.store.ts
└── __tests__/
    └── game.store.spec.ts
```

Имена:

- `*.spec.ts` для TypeScript;
- `*.spec.ts` для Vue-компонента через Vue Test Utils;
- описание теста формулирует наблюдаемое поведение.

## Что тестировать

### Unit

Обязательно проверить:

- нормализацию названий;
- точное сравнение с aliases;
- процентильные границы известности для всех пяти сложностей;
- ранжирование фильмов по составной оценке известности;
- сопоставление OCR-текста с русским, английским и альтернативными названиями;
- порядок пяти кадров по эвристике узнаваемости;
- переходы game state;
- сериализацию и валидацию localStorage;
- преобразование API errors.

### Component

Обязательно проверить:

- загрузочное состояние;
- отображение текущего кадра;
- отправку ответа с клавиатуры и кнопкой;
- блокировку повторной отправки;
- смену действия «Пропустить» на «Угадать» после выбора фильма;
- смену действия «Пропустить» на «Сдаться» на пятом кадре;
- выдачу русских и английских названий над полем поиска без перекрытия другими блоками;
- серую пометку и блокировку уже отправленного неверного фильма в повторной поисковой выдаче;
- переход к следующему кадру после пропуска и неверного ответа;
- встроенный результат победы с правильным ответом и переходом на следующий уровень;
- встроенный результат поражения с правильным ответом и повтором той же сложности;
- смену основного accent приложения вместе со сложностью;
- сброс на `easy` по кнопке «Далее» после победы в `impossible`;
- применение жанра и сохранение его при рестарте раунда;
- восстановление идентификатора раунда и жанра из localStorage;
- сохранение боковых панелей при загрузке нового кадра после смены режима;
- понятное состояние ошибки и повтор запроса;
- доступные имена ключевых controls.

### Router

Проверить:

- наличие всех маршрутов MVP;
- lazy pages без ошибки импорта;
- 404 для неизвестного пути;
- открытие игровой доски непосредственно на `/`.

## API в тестах

Тесты TMDB-клиента подменяют глобальный `fetch` и проверяют runtime-валидацию внешних ответов. Тесты stores и компонентов
подменяют публичные функции игрового API. Тестовые данные находятся только в тестовой инфраструктуре и не включаются в
приложение или production-сборку.

## Стиль теста

Использовать Arrange–Act–Assert без комментариев, если разделы очевидны. Проверять результат, доступный пользователю или публичному API, а не внутренние `ref` компонента.

Предпочтительно:

```ts
expect(wrapper.get('[role="status"]').text()).toContain('Неверный ответ')
```

Не следует привязываться к внутреннему классу shadcn-vue или Reka UI, если это не часть контракта.

## Snapshot tests

Большие snapshots страниц не используются. Маленький snapshot допустим для стабильной сериализованной структуры, если точечные assertions хуже объясняют контракт.

## Команды

```text
yarn test:unit
yarn test:unit:watch
yarn type-check
yarn lint
yarn format:check
yarn validate
```

Перед завершением значимого изменения выполняются `yarn validate` и `yarn build`.

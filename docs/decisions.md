# Журнал решений

## DEC-001: Vue SPA

**Статус:** принято.

Frontend создаётся как Vue 3 SPA на Vite с TypeScript, Pinia и Vue Router. SSR не требуется для MVP игры.

## DEC-002: Строгий TypeScript

**Статус:** принято.

Включён строгий TypeScript, `any` запрещён. Внешние данные рассматриваются как неизвестные до проверки на границе API.

## DEC-003: Сокращённый FSD

**Статус:** принято.

Используются `app`, `pages`, `features`, `shared`. Слои `entities` и `widgets` добавляются по фактической потребности, чтобы не создавать пустую архитектуру.

## DEC-004: Pinia Setup Stores

**Статус:** принято.

Все Pinia stores создаются функцией setup. Локальное UI-состояние не переносится в store без необходимости.

## DEC-005: Shared transport, feature API

**Статус:** принято.

Общий HTTP-клиент и инфраструктура находятся в `shared/api`; предметные запросы принадлежат feature. Компоненты не вызывают raw `fetch`.

## DEC-006: MSW вместо прямого mock-импорта

**Статус:** принято.

MSW перехватывает сетевой контракт в браузере и Vitest. Это позволяет заменить mock реальным backend без переписывания UI и stores.

## DEC-007: Afpia code style

**Статус:** принято.

Проект использует `@afpia/eslint`, `@afpia/prettier` и ESLint 9. `oxlint` и `oxfmt` удаляются, чтобы избежать конкурирующих правил.

## DEC-008: PrimeVue Aura

**Статус:** принято.

Для доступных базовых controls используется PrimeVue с Aura. Внешний вид адаптируется design tokens и обычным CSS.

## DEC-009: Ограниченное persistence

**Статус:** принято.

В localStorage сохраняются только текущая игра и тема. История и статистика откладываются до отдельного продуктового решения.

## DEC-010: Frontend-only MVP не является защищённой игрой

**Статус:** принято временно.

Mock-ответы доступны в клиентском bundle. Перед публичным рейтингом проверка ответа и очков обязательно переносятся на backend.

## DEC-011: Единое размещение инфраструктуры приложения

**Статус:** принято.

Все Pinia stores располагаются в `shared/stores`, Vue Router — в `app/router.ts`, а статические ресурсы и глобальные стили — в `shared/assets`. Папка `app/router/` создаётся только при реальной декомпозиции router на несколько файлов.

## DEC-012: Один сортировщик импортов

**Статус:** принято.

Импорты сортирует только `@afpia/prettier`. Сортировка импортов в ESLint отключена, чтобы автофиксы ESLint и Prettier не конкурировали.

## Как добавлять решение

Новое архитектурное решение добавляется отдельным разделом `DEC-NNN` со статусом, контекстом, решением и последствиями. Старое решение не удаляется: оно помечается заменённым и ссылается на новое.

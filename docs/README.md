# Документация Moviestr

Документация проекта организована по подходу Specification-Driven Development: сначала фиксируется наблюдаемое
поведение и критерии приёмки, затем меняются код и тесты.

## Иерархия документов

1. Явное актуальное решение владельца проекта.
2. Утверждённая функциональная спецификация из [`specs/`](./specs/README.md).
3. Инженерные стандарты проекта.
4. Архитектурные решения из [`decisions.md`](./decisions.md).
5. Существующий код и тесты.

При расхождении кода со спецификацией нельзя молча подгонять одно под другое. Нужно определить, изменилось ли требование,
обновить соответствующий документ и только затем менять реализацию.

## SDD-процесс изменения

1. Найти спецификацию затрагиваемого поведения и связанные requirement ID.
2. Если поведения ещё нет, создать спецификацию со статусом `черновик`.
3. Зафиксировать пользовательский сценарий, требования, ошибки, состояния и критерии приёмки.
4. После согласования перевести документ в статус `утверждено` и реализовать минимальный объём.
5. Добавить тесты, ссылающиеся в описании или таблице трассировки на requirement ID.
6. Выполнить проверки проекта и перевести спецификацию в статус `реализовано`.
7. При изменении поведения сначала обновить спецификацию, затем код и тесты.

Для исправления дефекта отдельная новая спецификация не нужна, если ожидаемое поведение уже однозначно задано.

## Статусы спецификации

- `черновик` — обсуждается, реализация не разрешена как окончательная.
- `утверждено` — требования согласованы и готовы к реализации.
- `реализовано` — требования представлены в коде и подтверждены тестами.
- `заменено` — документ сохранён для истории и содержит ссылку на новую спецификацию.

## Definition of Ready

Спецификация готова к реализации, когда определены:

- пользовательский результат и границы сценария;
- функциональные и нефункциональные требования;
- состояния загрузки, успеха, пустого результата и ошибки;
- данные, API-контракты и правила persistence;
- место реализации в FSD;
- проверяемые критерии приёмки и открытые вопросы.

## Definition of Done

Изменение завершено, когда:

- реализация соответствует утверждённым requirement ID;
- неизвестные внешние данные проверяются на границе API;
- бизнес-логика и значимое поведение компонентов покрыты тестами;
- таблица трассировки спецификации актуальна;
- успешно выполнены `yarn validate` и `yarn build`;
- создан отдельный атомарный коммит по правилам проекта.

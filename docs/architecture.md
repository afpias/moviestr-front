# Архитектура frontend

## Технологический стек

- Vue 3 и Composition API.
- TypeScript в строгом режиме.
- Vite для разработки и production-сборки.
- Pinia с Setup Stores.
- Vue Router с именованными ленивыми маршрутами.
- PrimeVue 5 с темой Aura.
- Обычный CSS и CSS custom properties.
- Fetch API для HTTP.
- MSW для mock API в браузере и тестах.
- Vitest и Vue Test Utils.
- Yarn как единственный менеджер пакетов.

Проект является только frontend-приложением. Backend и monorepo в текущую область работ не входят.

## Сокращённый FSD

Используются четыре слоя:

```text
src/
├── app/
├── pages/
├── features/
└── shared/
```

Направление зависимостей:

```text
app -> pages -> features -> shared
```

Нижний слой не импортирует верхний. Страницы не импортируют друг друга. Разные feature-slices не должны напрямую читать внутренние файлы соседней feature.

Слои `entities` и `widgets` не создаются заранее. Они добавляются только когда повторяющаяся предметная модель или самостоятельный крупный блок действительно используются несколькими страницами или features.

## Рекомендуемая структура

```text
src/
├── app/
│   ├── providers/
│   ├── router/
│   ├── styles/
│   └── App.vue
├── pages/
│   ├── home/
│   ├── game/
│   ├── rules/
│   ├── statistics/
│   └── not-found/
├── features/
│   ├── start-game/
│   ├── play-game/
│   ├── movie-search/
│   └── switch-theme/
└── shared/
    ├── api/
    │   ├── mock/
    │   └── client.ts
    ├── assets/
    ├── config/
    ├── lib/
    ├── types/
    └── ui/
```

Внутри feature создаются только реально нужные сегменты:

```text
features/play-game/
├── api/
├── lib/
├── model/
└── ui/
```

Папка из одного файла не создаётся без архитектурной причины. Если сегмент содержит один небольшой файл и не ожидается расширение, файл располагается в корне slice.

## Алиасы

| Алиас         | Путь                  |
| ------------- | --------------------- |
| `@/*`         | `src/*`               |
| `@app/*`      | `src/app/*`           |
| `@pages/*`    | `src/pages/*`         |
| `@features/*` | `src/features/*`      |
| `@shared/*`   | `src/shared/*`        |
| `@assets/*`   | `src/shared/assets/*` |

Правило выбора импорта:

- внутри одного небольшого модуля используются относительные импорты;
- между slices и слоями используются алиасы;
- импортировать внутренний файл slice извне можно только через его публичный `index.ts` после появления такого публичного API;
- `@/*` используется для временной миграции или пути, которому не подходит более точный алиас.

## Разделение ответственности

### Компонент

- отображает состояние;
- обрабатывает UI-события;
- вызывает действие feature или composable;
- не содержит raw `fetch`, правил начисления очков или сериализации localStorage.

### Composable

- связывает реактивное состояние и сценарий одного компонента или feature;
- находится рядом с потребителем;
- не становится глобальным только ради повторного использования одной строки кода.

### Pinia store

- хранит состояние, которое разделяется несколькими компонентами или должно пережить навигацию;
- описывает переходы бизнес-состояния;
- не хранит экземпляры компонентов, DOM-узлы и чисто визуальные флаги одного компонента.

### API

- `shared/api` содержит HTTP-клиент, общую обработку ошибок и MSW-инфраструктуру;
- конкретные запросы игры находятся в `features/<slice>/api`;
- компонент может инициировать запрос, но обращается к функции API или composable, а не вызывает `fetch` напрямую.

### Чистая логика

Нормализация названий, подсчёт очков и преобразование моделей реализуются чистыми функциями. Такие функции не читают Pinia, Router, DOM или localStorage и тестируются отдельно.

## Границы модулей

- Наружу экспортируется минимальный публичный API.
- Входные параметры и результаты функций имеют явные типы на публичной границе.
- Значения API не приводятся через `as` без проверки.
- Состояние ошибки моделируется явно, а не только сообщением в консоли.
- Циклические зависимости запрещены.

## Конфигурация окружения

Все переменные Vite объявляются в типах и начинаются с `VITE_`. Пример:

```text
VITE_API_BASE_URL=/api/v1
VITE_ENABLE_MOCKS=true
```

Секреты нельзя помещать во frontend-переменные: всё, что попадает в клиентскую сборку, доступно пользователю.

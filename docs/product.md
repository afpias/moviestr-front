# Продуктовая спецификация Moviestr

## Назначение

Moviestr — браузерная игра, в которой пользователь угадывает фильм по последовательно открывающимся кадрам. Основная
ценность одиночного режима — короткая игровая сессия и возможность выбрать подходящую сложность.

## MVP

В первую версию входят:

- непрерывная случайная игра без авторизации и отдельного стартового экрана;
- выбор фильма из тематической подборки;
- стартовая подборка `Топ 250` из рейтинга TMDB;
- пять режимов сложности: `easy`, `medium`, `hard`, `expert`, `impossible`;
- шесть последовательно открывающихся кадров на фильм;
- поиск по каталогу TMDB через автодополнение с отправкой только выбранного варианта;
- поиск и проверка русского, английского, оригинального и альтернативных названий;
- сохранение текущего состояния и темы в localStorage;
- игровая главная, страницы статистики-заглушки, правил и 404.

`Топ 250` формируется из первых 250 позиций метода TMDB `top_rated`. Это рейтинг TMDB, а не IMDb или Кинопоиска.
Пользовательский интерфейс содержит обязательную атрибуцию TMDB. Для локальной разработки нужен API Read Access Token.

## Режимы сложности

Сложность определяет диапазон позиции фильма в рейтинге TMDB:

| Режим      | Позиции TMDB |
| ---------- | ------------ |
| Easy       | 1–50         |
| Medium     | 51–100       |
| Hard       | 101–150      |
| Expert     | 151–200      |
| Impossible | 201–250      |

Игра начинается в `easy`. Режим можно переключить в любой момент без обязательного завершения предыдущего. После
верного ответа автоматически открывается следующий режим: `easy -> medium -> hard -> expert -> impossible`. После
верного ответа в `impossible` цикл полностью сбрасывается и начинается заново с `easy`.
В одиночном режиме очки не начисляются. Очки относятся к будущему многопользовательскому режиму, где участники будут
соревноваться друг с другом, и не должны появляться в текущем API или UI.

## Игровой сценарий

1. Пользователь открывает `/` и сразу видит первый кадр фильма сложности `easy`.
2. Пользователь может в любой момент выбрать другой режим сложности.
3. Пока фильм из автодополнения не выбран, основная кнопка называется «Пропустить» и открывает следующий кадр.
4. После выбора фильма из автодополнения кнопка меняется на «Угадать».
5. Неверный ответ открывает следующий кадр так же, как пропуск.
6. После шестого кадра пропуск или неверный ответ загружает новый фильм того же режима.
7. Верный ответ автоматически переводит на следующий режим.
8. Верный ответ в `impossible` сбрасывает цикл и переводит на новый фильм режима `easy`.
9. Текущее состояние восстанавливается после перезагрузки страницы.

Произвольный текст в поле не считается ответом, пока пользователь не выбрал фильм из списка автодополнения. Поэтому
можно нажать «Пропустить», не вводя название и не отправляя пустой ответ.

## Сравнение ответа

Перед сравнением обе строки нормализуются:

- переводятся в нижний регистр;
- `ё` заменяется на `е`;
- удаляются начальные и конечные пробелы;
- последовательности пробелов и знаков пунктуации приводятся к одному пробелу.

После нормализации требуется точное совпадение с одним из допустимых названий. Fuzzy matching и автоматическое исправление опечаток в MVP не используются.

## Маршруты MVP

- `/` — непрерывная игровая доска и переключение сложности.
- `/statistics` — локальная статистика; до расширения хранилища допускается информационная заглушка.
- `/rules` — правила игры и описание режимов сложности.
- `/:pathMatch(.*)*` — страница 404.

## Состояния интерфейса

Каждый пользовательский сценарий обязан иметь состояния:

- начальное;
- загрузка;
- успешные данные;
- пустой результат, если он возможен;
- восстанавливаемая ошибка с повторной попыткой;
- автоматический переход после правильного ответа или окончания кадров.

## Вне MVP

Пока не реализуются:

- регистрация и авторизация;
- профиль пользователя;
- глобальная таблица лидеров;
- многопользовательские соревнования и очки;
- друзья и социальные функции;
- публикация результата в виде emoji;
- административная панель;
- защищённый production backend;
- ежедневная игра;
- формальная синхронизация с внешним рейтингом фильмов.

Прямой доступ к TMDB из браузера остаётся ограничением frontend-прототипа. До публичного запуска токен, выбор фильма,
проверка ответа переносится на backend.

Эти возможности должны учитываться в контрактах, но не усложнять код MVP заранее.

## Критерии приёмки основной игры

- Игровая доска открывается сразу на `/`, без кнопки старта и отдельного публичного маршрута игры.
- До завершения раунда UI не получает правильный ответ в API-ответе.
- Одновременно виден только текущий кадр.
- Пропуск и неверный ответ увеличивают номер кадра ровно на один.
- На последнем кадре пропуск или неверный ответ заменяет фильм новым в том же режиме.
- Верный ответ повышает сложность на один уровень без начисления очков.
- Верный ответ в `impossible` очищает цикл и возвращает пользователя в `easy`.
- Выбранная сложность ограничивает фильм соответствующим диапазоном рейтинга TMDB.
- Режим можно переключить напрямую, не угадывая фильм текущего режима.
- Перезагрузка страницы восстанавливает текущее состояние и выбранную тему.
- Основной сценарий работает на ширине экрана от 360 px.

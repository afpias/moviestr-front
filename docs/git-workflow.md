# Git workflow

## Основное правило

После каждого завершённого самостоятельного действия создаётся отдельный атомарный коммит. Самостоятельным считается изменение, которое имеет один понятный результат, может быть проверено и не зависит от незавершённого кода в рабочем дереве.

Примеры самостоятельных действий:

- настройка одного инструмента;
- добавление законченного пользовательского сценария;
- исправление конкретного дефекта;
- добавление тестов для одного поведения;
- обновление спецификации для одного решения;
- рефакторинг одного модуля без изменения поведения.

Не являются самостоятельным действием:

- исследование без изменения результата;
- временный лог или отладочный код;
- часть функции, которая не собирается или не проверяется;
- форматирование, необходимое только для текущей feature;
- случайная группа несвязанных файлов.

## Атомарность

Перед коммитом необходимо:

1. Просмотреть изменения и исключить посторонние файлы.
2. Добавить в index только файлы текущего действия.
3. Выполнить проверки, соответствующие риску изменения.
4. Создать сообщение, проходящее `@afpia/commitlint`.
5. Убедиться, что hook `commit-msg` завершился успешно.

Завершённое действие не оставляется незакоммиченным, если пользователь явно не попросил не создавать коммит.

## Формат сообщения

```text
<emoji> <type>(<optional-scope>): <subject>

<optional-body>

<optional-footer>
```

Примеры:

```text
✨ feat(game): добавления подсчёта очков
🐛 fix(router): исправления восстановления игрового раунда
📚 docs(api): описания контракта ответа
🛠️ build(tooling): настройки проверки коммитов
```

Требования preset:

- заголовок не длиннее 100 символов;
- заголовок и type в lowercase;
- точка в конце заголовка запрещена;
- subject обязателен;
- перед body и footer требуется пустая строка;
- строки body и footer не длиннее 100 символов.

`type` и `scope` остаются техническими латинскими идентификаторами. Subject пишется на русском языке в форме родительного падежа и
описывает результат изменения: `добавления`, `исправления`, `обновления`, `настройки`, `рефакторинга`.

Грамматическая форма является командным соглашением и проверяется при review: commitlint контролирует структуру, emoji, type, регистр и
длину, но не способен автоматически определить падеж русского текста.

## Типы и emoji

| Emoji | Type       | Назначение                                        |
| ----- | ---------- | ------------------------------------------------- |
| ✨    | `feat`     | Новая пользовательская или предметная возможность |
| 🐛    | `fix`      | Исправление дефекта                               |
| 📚    | `docs`     | Только документация                               |
| 💎    | `style`    | Форматирование без изменения поведения            |
| 🚀    | `refactor` | Перестройка кода без изменения поведения          |
| 🚨    | `test`     | Добавление или исправление тестов                 |
| 🛠️    | `build`    | Сборка, зависимости и инструменты                 |
| ♻️    | `chore`    | Обслуживание репозитория                          |
| 🗑️    | `revert`   | Отмена предыдущего коммита                        |
| 🔥    | `init`     | Инициализация проекта                             |

Scope необязателен. Если используется, он должен кратко называть затронутую область: `game`, `api`, `router`, `ui`, `tooling`, `docs`.

## Команды

Интерактивное создание сообщения:

```text
yarn commit
```

Проверка сообщения из stdin:

```text
echo "🛠️ build(tooling): настройки проверки коммитов" | yarn commitlint
```

Проверка существующего коммита:

```text
yarn commitlint --from HEAD~1 --to HEAD --verbose
```

Git hook автоматически запускает:

```text
yarn commitlint --edit .git/COMMIT_EDITMSG
```

Обход hook через `--no-verify` запрещён, кроме явно согласованного аварийного случая.

## Проверки перед коммитом

- Документация: `yarn format:check` и `yarn lint`.
- Код или тесты: `yarn validate`.
- Зависимости, Vite или production-конфигурация: `yarn validate` и `yarn build`.

Если проверка не может быть выполнена из-за внешнего ограничения, причина фиксируется в отчёте пользователю. Известно неисправное изменение не коммитится.

## История

- Не использовать `git commit --amend` без прямого запроса пользователя.
- Не переписывать опубликованную историю.
- Не объединять уже созданные атомарные коммиты без прямого запроса.
- Не использовать `git reset --hard` или принудительный push.

# Стиль кода

## Автоматические источники правил

- ESLint: `@afpia/eslint` на ESLint 9.
- Prettier: `@afpia/prettier`.
- TypeScript: строгая проверка через `vue-tsc`.

Не добавлять параллельные линтеры и форматтеры. `oxlint` и `oxfmt` в проекте не используются.

Основные параметры форматирования из `@afpia/prettier`:

- табы, визуальная ширина таба — 2;
- максимальная ширина форматирования — 130;
- точки с запятой не ставятся;
- trailing comma не ставится;
- строки TypeScript оформляются одинарными кавычками;
- параметры стрелочной функции всегда заключаются в скобки.

Форматирование выполняет инструмент. Ручные пробелы для визуального выравнивания не используются.

## TypeScript

- `strict` обязателен.
- `any` запрещён. Для неизвестного значения применяется `unknown` и последующее сужение типа.
- Не использовать `as` для скрытия ошибки модели. Assertion допустим после runtime-проверки или при ограничении платформы, которое невозможно выразить иначе.
- Для конечных состояний использовать union types.
- Для расширяемых объектных контрактов использовать `interface`, для unions и вычисляемых типов — `type`.
- Публичные функции, API-контракты и props должны иметь явные типы.
- Не использовать TypeScript `enum`; применять `as const` или строковые unions.
- Не применять non-null assertion `!`, если корректность можно выразить проверкой.

```ts
const GAME_STATUSES = ['idle', 'loading', 'playing', 'won', 'lost', 'error'] as const

export type GameStatus = (typeof GAME_STATUSES)[number]
```

## Экспорты

Именованные экспорты используются по умолчанию:

```ts
export function normalizeMovieTitle(value: string): string {
	return value.trim().toLocaleLowerCase('ru-RU')
}
```

`export default` допускается только там, где это ожидает инструмент или Vue-экосистема: конфигурационные файлы, router instance и SFC.

Barrel-файлы `index.ts` создаются только как публичная граница slice. Глубокая цепочка barrel-файлов запрещена.

## Именование

| Сущность             | Формат                       | Пример                |
| -------------------- | ---------------------------- | --------------------- |
| Vue-компонент        | PascalCase                   | `MovieFrame.vue`      |
| TypeScript-файл      | kebab-case с ролью           | `game.store.ts`       |
| Composable           | `use` + PascalCase           | `useGameRound`        |
| Pinia store          | `use` + PascalCase + `Store` | `useGameStore`        |
| Тип или интерфейс    | PascalCase                   | `GameRound`           |
| Функция и переменная | camelCase                    | `normalizeMovieTitle` |
| Boolean              | `is`, `has`, `can`, `should` | `isGameFinished`      |
| Константа модуля     | UPPER_SNAKE_CASE             | `MAX_GAME_ATTEMPTS`   |
| CSS-класс            | kebab-case                   | `.game-result`        |
| Route name           | kebab-case string            | `game-round`          |

Имена описывают назначение, а не техническую форму. Не использовать `data`, `item`, `value`, `handler` без контекста.

## Vue SFC

Порядок блоков фиксирован:

```vue
<script setup lang="ts"></script>

<template></template>

<style scoped></style>
```

Внутри `<script setup>` придерживаться порядка:

1. импорты;
2. типы props и emits;
3. `defineProps`, `defineEmits`, `defineModel`;
4. зависимости и stores;
5. локальное состояние;
6. computed;
7. функции и обработчики;
8. watchers и lifecycle hooks.

Дополнительные правила:

- props считаются readonly;
- события имеют типизированные payload;
- тяжёлая бизнес-логика выносится из SFC;
- не создавать computed с побочными эффектами;
- watcher используется для синхронизации, а не вместо обычного действия;
- DOM-доступ выполняется через template refs и только при реальной необходимости.

## Импорты

- Сначала внешние пакеты, затем алиасы проекта, относительные пути и стили.
- Сортировку выполняет Prettier через `@afpia/prettier`; ESLint дополнительно проверяет порядок.
- Использовать `import type` для типов, не нужных в runtime.
- Не импортировать модуль через путь длиннее его публичной границы без причины.
- Не использовать абсолютные filesystem-пути.

## Функции и обработка ошибок

- Одна функция решает одну задачу.
- Guard clauses предпочтительнее глубокой вложенности.
- Ошибка внешней системы преобразуется в тип проекта на границе `shared/api`.
- Пустой `catch` запрещён.
- `console.log` не используется в рабочем коде; диагностические `console.warn` и `console.error` допустимы только на инфраструктурной границе.
- Текст для пользователя не берётся напрямую из неизвестного server error.

## CSS

- Используется обычный CSS.
- Стили компонента по умолчанию имеют `scoped`.
- Глобальные reset, typography и design tokens располагаются в `app/styles`.
- Цвета, интервалы, радиусы и тени повторного использования задаются CSS custom properties.
- В компоненте запрещены случайные hex-цвета, если существует подходящий token.
- Не использовать `!important`, кроме документированного исправления стороннего компонента.
- Не стилизовать внутреннюю разметку PrimeVue через хрупкие селекторы; использовать tokens и Pass Through API.
- Mobile-first media queries являются стандартом.

## Язык

- Идентификаторы и код — на английском.
- Документация — на русском.
- Пользовательский интерфейс MVP — на русском.
- Комментарии добавляются только для неочевидного решения и должны объяснять причину, а не повторять код.

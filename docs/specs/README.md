# SDD-пакеты

Каждая возможность хранится в отдельной директории и содержит только три документа:

```text
feature-name/
├── spec.md
├── plan.md
└── tasks.md
```

- `spec.md` определяет наблюдаемое поведение и не описывает детали реализации.
- `plan.md` связывает требования с архитектурой, API, данными и проверками.
- `tasks.md` содержит атомарные задачи в порядке выполнения.

Новую возможность создавать копированием [`_template`](./_template/spec.md). До согласования `spec.md` имеет статус
`черновик`; реализация начинается после фиксации границ и критериев приёмки. Изменение поведения сначала отражается в
`spec.md`, затем в `plan.md` и `tasks.md`. Исправление реализации без изменения контракта не требует нового пакета.

Идентификаторы требований уникальны и стабильны. Выполненная задача отмечается только после реализации и проверки.

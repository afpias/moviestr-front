# SPEC-008: Проверки PR и бот-ревьюер

| Поле                 | Значение                          |
| -------------------- | --------------------------------- |
| Статус               | согласовано, подключение поэтапно |
| Последнее обновление | 2026-10-18                        |
| Зависимости          | GitHub Actions, OpenAI API        |

## Цель

Проверять pull requests автоматически, сохраняя ручное решение владельца о слиянии.

## Границы

Входят CI, анализ diff и контекста, комментарии, Approve / Request changes, инструкция подключения GitHub App.
Не входят автоматическое исправление кода, merge, деплой, backend игры и выполнение команд моделью.

## Требования

- **REV-001.** PR в `dev` и `main` запускает обязательные `Validate` и `Build` без секретов.
- **REV-002.** Обе ветки запрещают прямой push, force push и удаление; проваленные проверки блокируют merge.
- **REV-003.** Бот проверяет новую версию недрафтового PR доверенного автора в этом же репозитории.
- **REV-004.** Ревью учитывает diff, содержимое изменённых текстовых файлов, правила базовой ветки и SDD-пакеты.
- **REV-005.** Подтверждённые P0–P2 дают Request changes, только P3 не блокируют Approve. Замечания публикуются
  по-русски в изменённых строках; подробности вне строки включаются в итоговый текст.
- **REV-006.** Неполный ответ, превышение лимита контекста, ошибка API или отсутствие секретов не дают Approve.
- **REV-007.** Результат привязан к SHA, PR и базовой ветке; устаревший запуск не одобряет обновлённый PR.
- **REV-008.** Код PR не выполняется в jobs с секретами. API-ключ и токен GitHub App находятся в разных jobs.
- **REV-009.** После подключения бот публикует статус `AI review`; статус становится обязательным только после
  установки workflow в целевую ветку и успешного пробного запуска. Требование одного approval включается на этом этапе.
- **REV-010.** Владелец самостоятельно создаёт и устанавливает GitHub App, добавляет секреты и выбирает API-модель.
  Merge остаётся исключительно ручным действием.

## Состояния и ошибки

CI: pending → success / failure. AI: pending → success / failure; без настроенной интеграции запуск завершается ошибкой.
Fork PR и авторы без write-доступа не получают секретов и автоматического одобрения. Для них нужен отдельный ручной
процесс сопровождения; секреты в fork не передаются. Draft не анализируется до ready for review.

## Сценарии приёмки

- **AC-01:** при ошибке теста `Validate` красный, merge в защищённую ветку запрещён.
- **AC-02:** полный ответ без P0–P2 даёт Approve и зелёный `AI review` на проверенном SHA.
- **AC-03:** подтверждённый P2 даёт Request changes и красный статус; комментарий относится к diff.
- **AC-04:** новый коммит, незавершённый JSON, отказ модели, лимит контекста или отсутствующий секрет не дают Approve.
- **AC-05:** проверка fork PR не использует OpenAI key и GitHub App credentials.

## Нефункциональные требования

Доверенные скрипты читаются из точного SHA базовой ветки. Модель получает только данные и не имеет tools.
Один запрос на ревью, таймаут 180 секунд, максимум 250 000 символов входных данных и 12 000 output tokens.
GitHub App имеет только Contents read, Pull requests write, Commit statuses write и Metadata read.

# Инженерный стандарт: состояние и маршрутизация

Наблюдаемое восстановление игры определяет [SPEC-005](./specs/SPEC-005-persistence-theme.md). Этот документ задаёт
правила размещения состояния и конфигурации router.

## Правило размещения состояния

Использовать наименьшую подходящую область жизни:

1. `ref` в компоненте — состояние нужно только одному компоненту.
2. Feature composable — состояние и сценарий разделяются внутри одной feature.
3. Pinia store — состояние нужно нескольким несвязанным компонентам, нескольким страницам или оно должно пережить навигацию.
4. localStorage — только явно утверждённое долговременное состояние.

В текущей версии в localStorage сохраняются только:

- текущее состояние непрерывной игры;
- выбранная светлая или тёмная тема.

`search-movie` хранит идентификаторы неверно выбранных фильмов в feature composable только до конца текущего раунда.
Эта история нужна полю автодополнения и отправке ответа, не записывается в Pinia или localStorage и очищается при
загрузке нового фильма.

Полная сессия раунда хранится в `sessionStorage` локальным адаптером. Результаты прошлых игр, победы, серии и глобальная
статистика пока не сохраняются.

## Pinia

Используются только Setup Stores:

Все Pinia stores располагаются в `shared/stores`. Там находятся `game.store.ts` и `theme.store.ts`. Компоненты и features
обращаются к store через алиас `@shared`, а не через глубокие относительные пути.

```ts
export const useGameStore = defineStore('game', () => {
	const status = ref<GameStatus>('idle')

	function initializeGame(): void {
		status.value = 'loading'
	}

	return {
		initializeGame,
		status
	}
})
```

Store обязан экспортировать только состояние и действия, нужные потребителям. Внутренние детали не возвращаются для удобства теста.

### Game store

Минимальная модель состояния:

```ts
interface ActiveGameState {
	currentFrameIndex: number
	difficulty: Difficulty
	genre: GameGenre
	lastError: string | null
	status: GameStatus
	totalFrames: 5
}

type GameStatus = 'error' | 'idle' | 'loading' | 'lost' | 'playing' | 'submitting' | 'won'
```

Разрешённые основные переходы:

```text
idle -> loading -> playing
playing -> submitting -> playing
playing -> submitting -> loading -> playing
loading|submitting -> error -> предыдущее восстанавливаемое состояние
```

Двойная отправка во время `submitting` блокируется. После завершения store сохраняет результат и переходит в `won` или
`lost`. Продолжение из `won` выбирает следующий уровень и возвращает `impossible` к `easy`; повтор из `lost` загружает
новый фильм той же сложности. Явный рестарт возвращает сложность к `easy`, но не изменяет жанр.

### Theme store

Theme store хранит только `'light' | 'dark'`, применяет класс темы к корневому элементу и синхронизируется с localStorage. Системная тема может использоваться как начальное значение, если сохранённого выбора нет.

## Persistence

Доступ к localStorage выполняется через адаптер, а не напрямую из компонентов или stores.

Ключи имеют namespace и версию:

```text
moviestr:game:v2
moviestr:theme:v1
```

При чтении данные проверяются. Повреждённая или неизвестная версия удаляется только для соответствующего ключа и заменяется безопасным начальным значением.

В localStorage не сохраняются:

- правильный ответ до окончания игры;
- секреты и API-ключи;
- полные изображения;
- экземпляры ошибок и реактивные объекты Vue.

`sessionStorage` может хранить полную локальную игровую сессию frontend-прототипа. Это временная реализация до появления
backend и не отменяет запрет на хранение секретов.

## Router

Router располагается в `app/router.ts`. Папка `app/router/` создаётся только после декомпозиции конфигурации на несколько файлов.

Все маршруты именованные. Компоненты страниц загружаются лениво. Реализованные маршруты:

```text
/                  home
/:pathMatch(.*)*   not-found
```

Имена и пути маршрутов объявляются рядом с router-конфигурацией. Строки маршрутов не дублируются по компонентам.

```ts
export const ROUTE_NAMES = {
	home: 'home',
	notFound: 'not-found'
} as const
```

### Route meta

Meta типизируется через расширение `RouteMeta`. Минимальные поля:

- `title` — заголовок страницы;
- `layout` — только после появления нескольких layouts;
- `requiresAuth` — добавляется только вместе с утверждённой авторизацией.

Navigation guards отвечают только за навигационные правила. Они не загружают весь раунд и не заменяют feature-actions.

## Игровой маршрут и восстановление

Игра находится непосредственно на `/`. Публичный маршрут вида `/game/:id` не используется. При открытии страницы store
восстанавливает внутренний идентификатор сессии и выбранный жанр из `moviestr:game:v2`, если запись валидна, или
автоматически загружает новый фильм сложности `easy` со всеми жанрами. Внутренний идентификатор не отображается
пользователю и не является частью URL.

Ссылка `/lobby` уже присутствует в навигации как направление развития, но маршрут и функциональность не реализованы.
До утверждения отдельной multiplayer-спецификации он обрабатывается общей страницей 404 и не считается готовым сценарием.

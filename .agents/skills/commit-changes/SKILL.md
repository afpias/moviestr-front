# Коммит завершённой части работы

Прочитать разделы «Рабочий процесс» и «Git» в [AGENTS.md](../../../AGENTS.md).
Коммит завершённой реализации уже разрешён правилами проекта; повторно спрашивать разрешение не нужно.
Этот скилл не разрешает push, публикацию, переписывание истории или включение посторонних изменений.

1. Проверить `git status --short`, `git diff` и `git diff --cached`. Выделить одну законченную смысловую часть.
   Учитывать исходные изменения пользователя, включая заранее staged файлы. Не очищать чужой index и не включать
   его содержимое в свой коммит. При пересечении отделить свои hunks; если надёжно отделить нельзя, запросить решение.
2. Использовать результаты [verify-changes](../verify-changes/SKILL.md). Если проверок ещё не было, выполнить их.
   Не коммитить заведомо сломанную реализацию. Посторонние ошибки полного прогона явно описать; отдельный коммит допустим
   лишь для самостоятельно проверенной части, без утверждения об успешности всего проекта.
3. Добавить в index только относящиеся к действию пути или hunks. Проверить `git diff --cached --stat`,
   `git diff --cached --check` и полный staged diff: нет секретов, случайных файлов и чужих правок.
4. Составить сообщение по формату из AGENTS.md: правильная пара emoji/type, технический scope, русский subject
   с отглагольным существительным в именительном падеже. Сверить сообщение с текущим commitlint; не менять
   конфигурацию линтера ради прохождения одного сообщения.
5. Создать обычный коммит с включёнными hooks. При ошибке исправить её причину в рамках задачи; не применять `--no-verify`.
   Если завершить коммит мешают права доступа, запросить требуемое разрешение инструмента, не обходить ограничение.
6. Проверить `git show --stat --oneline HEAD` и `git status --short`. Сообщить hash, смысл изменения, результаты
   проверок и оставшиеся ограничения. Не требовать чистого worktree, если в нём сохранены изменения пользователя.

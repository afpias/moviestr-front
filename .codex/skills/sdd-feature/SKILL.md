# Создание и изменение функциональности

Прочитать [AGENTS.md](../../../AGENTS.md) и [индекс спецификаций](../../../docs/README.md).
Определить, меняет ли запрос функциональность или только восстанавливает ожидаемое поведение.
Для технического исправления следовать сокращённому процессу из AGENTS.md.

## Spec → Plan → Tasks

1. Найти затронутый пакет `docs/<feature>` и прочитать все три документа и связанный код. Сохранить существующие
   requirement ID. Зафиксировать расхождения кода с требованиями: исправлять дефект, а не переписывать требования под него.
2. Для новой возможности использовать [шаблон](../../../docs/_template/spec.md), включая соседние `plan.md` и `tasks.md`.
   Заполнить требования из запроса и предыдущих решений владельца. Уточнить только выбор, существенно влияющий на
   поведение, границы или внешнюю систему. Отсутствие пакета не является причиной останавливать понятную задачу.
3. В `spec.md` описать цель, границы, проверяемые требования, состояния, ошибки и сценарии приёмки. Не выдавать
   неподтверждённые предположения за решения владельца; статус нового пакета до согласования — `черновик`.
4. В `plan.md` определить FSD slices, ответственность `model/api/ui/lib`, публичные контракты, данные, риски и проверки.
   Использовать существующий стек и UI-компоненты согласно AGENTS.md.
5. В `tasks.md` связать атомарные задачи с requirement ID и способом проверки. Для нового пакета добавить ссылку
   в `docs/README.md`. В существующем пакете менять только затронутые требования и этапы.

## Implement → Verify

Реализовать согласованный объём по задачам. Уже данный запрос на реализацию и ответы владельца не требуют повторного
разрешения. Если остался существенный открытый вопрос, продолжать независимые задачи и уточнить зависимую часть.

Применить [verify-changes](../verify-changes/SKILL.md). Отмечать задачи выполненными только после реализации и проверки;
отразить фактическую трассировку требований. Не присваивать статус «реализовано» незавершённому пакету.
Завершённую проверенную часть передать в [commit-changes](../commit-changes/SKILL.md).
Если запрошены только спецификации или план, закончить на документах: этот скилл не разрешает реализацию сам по себе.
